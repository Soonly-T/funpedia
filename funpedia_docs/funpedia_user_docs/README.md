This reference documents the Flutter application in `../../funpedia_user` as it currently exists. API entries come first and use a consistent lookup pattern: symbol and arguments, purpose, then example. The page guide follows the API reference. Placeholder behavior and unused metadata are called out rather than described as finished features.

## Project Snapshot — 2026-10-07

This section summarizes the current prototype and supersedes older page notes below where they disagree.

### Implemented in the user app

- The home page currently has **12 statically defined subjects**. Each has a stable `slug`; subject data is not being fetched from Supabase yet.
- `SubjectDefinition.fromJson` can parse a row using the planned Supabase column names: `index`, `name`, `color`, `slug`, `icon_key`, `press_jingle`, and `hover_tone`. It parses `#RRGGBB` colors, a PostgreSQL `text[]` jingle, and note names such as `F#3` into frequencies.
- `icon_key` is resolved through a **bundled Flutter icon map** with a fallback icon. A new database row can use any already-mapped key without changing its display name, but adding a brand-new icon key still requires updating the app's map (or later adopting remotely cached image assets).
- The subject page is responsive: portrait uses a left navigation drawer opened from the subject header; landscape uses a persistent, initially expanded, collapsible topic column. There is no app bar. The topic grid has fixed 128×128 document tiles, calculates columns from the available width, and pads the last row with invisible slots for alignment.
- Topic names are still local/static. Selecting one opens an **article placeholder page**, not a real article. The desktop search field filters the grid's topic labels; the sort control currently changes its icon/state but does not yet reorder the results.
- `window_manager` is initialized for native Windows, Linux, and macOS. The app-level F11 handler toggles native fullscreen. After adding/changing a native plugin, fully stop and relaunch the app; hot restart alone can produce `MissingPluginException`. Escape is not currently configured to pop navigation.

### Authoring and content decisions

- The admin portal is a separate Flutter project at [`../../funpedia_admin`](../../funpedia_admin). Its current editor is a local draft-authoring prototype with structured blocks and Markdown/JSON export; it is **not yet saving to Supabase**.
- Keep the content hierarchy to three levels: **subject → topic → article**. “Interactives” describes a content format/browse view, not a subject taxonomy. A real Flutter interactive can be a standalone feature and may later be linked from an article.
- Store article revisions as structured JSON block documents in Supabase Postgres; Markdown is an import/export format, not the canonical representation. Store media bytes in Supabase Storage and media metadata/references in Postgres.
- Supabase is the selected BaaS. The backend, publishing workflow, and device-offline cache/sync are design decisions only; Supabase and Drift are not wired into the user app yet. The exact sync mechanism (for example, PowerSync versus custom sync) remains open.
- Offline target: cache article/revision data in a local SQLite database and media files in the app's documents directory; only mark an article offline-ready after all required assets download and verify.

See the fuller [content and backend architecture notes](../../funpedia_user/docs/content-architecture.md).

### Subject Supabase Row Contract

The planned `subjects` row uses the following application-facing columns. The table is not deployed or connected to the app yet.

| Column         | PostgreSQL type | Rule / meaning                                                                                              |
| -------------- | --------------- | ----------------------------------------------------------------------------------------------------------- |
| `id`           | `uuid`          | Primary key, generated by `gen_random_uuid()`; inherently unique and non-null.                              |
| `created_at`   | `timestamptz`   | Non-null, default `now()`.                                                                                  |
| `index`        | `int8`          | Non-null and unique; controls subject ordering.                                                             |
| `name`         | `text`          | Non-null and unique display name.                                                                           |
| `color`        | `text`          | Non-null and unique among the current subject rows; stored as `#RRGGBB`.                                    |
| `press_jingle` | `text[]`        | Non-null and unique; current values contain four note-name strings.                                         |
| `hover_tone`   | `text`          | Non-null single note name; **not unique**, because current subjects reuse `G3` and `A3`.                    |
| `slug`         | `text`          | Non-null and unique stable identifier, e.g. `earth-science`.                                                |
| `icon_key`     | `text`          | Non-null semantic key resolved by the app's bundled icon map; it is not Flutter `IconData` or a code point. |

The app's `SubjectDefinition.fromJson` expects these names and compatible Supabase JSON values. Adding a row with a new icon key not present in the app's bundled map currently falls back to the default icon; supporting arbitrary new icons without an app release would require a remotely stored image-asset option or a complete dynamic icon catalog.

### Domain Types

#### `MusicalNote(String name, double frequency)`

**Arguments:** `name`, readable pitch label; `frequency`, pitch in hertz.  
**Purpose:** Immutable value object used by the note catalog, subject definitions, and audio synthesis.  
**Example:**

```dart
const note = MusicalNote('C4', 261.63);
```

#### `MusicalNote.toString()`

**Arguments:** none.  
**Purpose:** Returns the note's readable `name`.  
**Example:**

```dart
print(Note.c4); // C4
```

#### `Note` constants

**Arguments:** none; constants are referenced by name.  
**Purpose:** Predefined `MusicalNote` values from `Note.b2` through `Note.d6`, including sharp and flat spellings where defined. Use these constants instead of repeating frequency literals.  
**Example:**

```dart
const melody = <MusicalNote>[Note.c4, Note.e4, Note.g4, Note.c5];
```

#### `SubjectDefinition({...})`

**Arguments:** required named fields `index` (`int`), `name` (`String`), `color` (`Color`), `icon` (`IconData`), `slug` (`String`), `pressJingle` (`List<MusicalNote>`), and `hoverTone` (`MusicalNote`).
**Purpose:** Immutable metadata for a home-page subject card. `slug` is the stable content/URL identifier; navigation still uses `Navigator.push`. `fromJson` parses the planned Supabase row shape, including color, `text[]` note names, and `icon_key`. Icon keys must exist in the app's `subject_icons.dart` map or the fallback icon is used.
**Example:**

```dart
const subject = SubjectDefinition(
  index: 0,
  name: 'History',
  color: Color(0xFF8D6E63),
  icon: Icons.account_balance,
  slug: 'history',
  pressJingle: [Note.d3, Note.a3, Note.fs3, Note.d4],
  hoverTone: Note.d3,
);
```

### Subject Motifs

#### `SubjectJingles.all`

**Arguments:** none.  
**Purpose:** Static catalog of 17 four-note candidate motifs. The subject mapping below selects entries by index.  
**Example:**

```dart
final candidate = SubjectJingles.all.first;
```

#### `SubjectJingles.forSubject(String subject)`

**Arguments:** `subject`, the exact subject display name.  
**Purpose:** Returns the mapped motif. Unknown names fall back to `all[0]`; callers should use one of the names defined on `HomePage`.  
**Example:**

#### `_SubjectCardState._playHoverTone()`

**Arguments:** none; reads `widget.subject.hoverTone`.  
**Purpose:** Debounces pointer-enter audio by 90 ms, then plays the subject's hover note.

**Arguments:** none.  
**Purpose:** Cancels a pending hover timer, asynchronously disposes the audio service, then disposes the widget state.

### Audio Service

#### `SubjectAudioPlayer()`

**Arguments:** none.  
**Purpose:** Creates a lightweight service. Each playback method creates its own `AudioPlayer` and disposes it after completion.  
**Example:**

```dart
final audio = SubjectAudioPlayer();
```

#### `SubjectAudioPlayer.playNote(MusicalNote note)`

**Arguments:** `note`, the pitch to synthesize.  
**Purpose:** Generates and plays one short kalimba-like note at the note volume.  
**Example:**

```dart
audio.playNote(Note.c4);
```

#### `SubjectAudioPlayer.playHoverNote(MusicalNote note)`

**Arguments:** `note`, normally the subject's hover pitch.  
**Purpose:** Generates and plays one hover sample using the shared UI audio context.  
**Example:**

```dart
audio.playHoverNote(subject.hoverTone);
```

#### `SubjectAudioPlayer._playHoverSample(AudioPlayer player, List<double> samples)`

**Arguments:** `player`, one-shot player; `samples`, normalized mono samples.  
**Purpose:** Sets hover volume, encodes samples as WAV, waits for completion, then disposes the player in `finally`.  
**Example:**

```dart
await _playHoverSample(player, samples);
```

#### `SubjectAudioPlayer.playMelody(Iterable<MusicalNote> notes, {bool reverse = false})`

**Arguments:** `notes`, pitches to synthesize; optional `reverse`, which plays the sequence backwards. Empty sequences return without playing.  
**Purpose:** Mixes overlapping note samples into one buffer, smooths it, and plays the result. Notes start 110 ms apart and last 220 ms.  
**Example:**

```dart
audio.playMelody(SubjectJingles.forSubject('Physics'));
audio.playMelody(SubjectJingles.forSubject('Physics'), reverse: true);
```

#### `SubjectAudioPlayer._smoothMelody(List<double> samples)`

**Arguments:** `samples`, the mixed melody buffer.  
**Purpose:** Applies a one-pole smoothing filter with a 0.22 coefficient. Empty input is returned unchanged.  
**Example:**

```dart
final smoothed = _smoothMelody(mixedSamples);
```

#### `SubjectAudioPlayer._playOneShot(AudioPlayer player, List<double> samples, {required double volume})`

**Arguments:** `player`; `samples`; required `volume`.  
**Purpose:** Encodes a buffer, plays it, waits for completion, and disposes the player in `finally`.  
**Example:**

```dart
await _playOneShot(player, samples, volume: _melodyVolume);
```

#### `SubjectAudioPlayer._synthesizeKalimbaNote(double frequency)`

**Arguments:** `frequency`, pitch in hertz.  
**Purpose:** Produces 240 ms of mono samples using a fundamental tone, quiet harmonics, and attack/decay/release envelopes at 44.1 kHz.  
**Example:**

```dart
final samples = _synthesizeKalimbaNote(Note.c4.frequency);
```

#### `SubjectAudioPlayer._buildWaveBytes(List<double> samples)`

**Arguments:** normalized mono `samples`.  
**Purpose:** Writes a little-endian, mono, 16-bit PCM WAV buffer at 44.1 kHz and adds 24 ms of silence at both ends.  
**Example:**

```dart
final bytes = _buildWaveBytes(samples);
await player.play(BytesSource(bytes));
```

#### `SubjectAudioPlayer._isSupported`

**Arguments:** none.  
**Purpose:** Returns true for Android, iOS, Linux, Windows, and macOS. Playback entry points return early on other platforms. The `dart:io` dependency means web needs a conditional implementation before it can be supported.  
**Example:**

```dart
if (!_isSupported) return;
```

#### `SubjectAudioPlayer._ascii(String value)`

**Arguments:** `value`, an ASCII chunk for a WAV header.  
**Purpose:** Returns the string's code units as bytes.  
**Example:**

```dart
buffer.add(_ascii('RIFF'));
```

#### `SubjectAudioPlayer._int16(int value)`

**Arguments:** signed integer value.  
**Purpose:** Encodes the low 16 bits as two little-endian bytes for the WAV header or sample data.  
**Example:**

```dart
buffer.add(_int16(bitsPerSample));
```

#### `SubjectAudioPlayer._int32(int value)`

**Arguments:** integer value.  
**Purpose:** Encodes 32 bits as four little-endian bytes for WAV sizes and sample rate.  
**Example:**

```dart
buffer.add(_int32(sampleRate));
```

#### `SubjectAudioPlayer.dispose()`

**Arguments:** none.  
**Purpose:** Returns a completed future; the service holds no persistent player to release. One-shot routines dispose their own players when playback completes.  
**Example:**

```dart
await audio.dispose();
```

## Pages

### Home Page

**Implementation:** [`home_page.dart`](../../funpedia_user/lib/features/home/presentation/home_page.dart)  
**Widget:** `HomePage`  
**State owner:** `_HomePageState`

The home page currently defines twelve subjects in `_HomePageState.subjects`. Portrait uses one vertically scrolling list. Landscape distributes even indices to the first column and odd indices to the second. The breakpoint is orientation-based (`height < width`), not a fixed pixel width.

Each `SubjectDefinition` supplies the card label, icon, color, index, slug, stored jingle, and hover note. `SubjectCard` uses the name to look up the played motif in `SubjectJingles`; `SubjectDefinition.pressJingle` is currently not authoritative. When a card is activated, the looked-up motif is passed to `SubMenu` so the back button can reverse the same sequence. `slug` is stable content identity, but is not yet used for URL routing.

**Interaction flow:** pointer enters card -> 90 ms debounce -> hover note; pointer down -> press motif; button activation -> push `SubMenu` with a 300 ms forward slide; back tap -> reverse motif and pop route.

### Subject Menu Page

**Implementation:** [`subject_menu_page.dart.dart`](../../funpedia_user/lib/features/home/presentation/subject_menu_page.dart.dart)  
**Widget:** `SubMenu`  
**State owner:** `_SubMenuState`

Portrait layout keeps the subject header visible and opens a left drawer from its menu button. The drawer is full-width below 384 logical pixels and otherwise at most 384 pixels wide. Landscape has no app bar or drawer: it uses a persistent topic-navigation column, initially expanded and collapsible, next to the topic grid. The subject header appears at the top of that navigation column.

The grid uses 128×128 document-icon tiles. Its column count is calculated from the width remaining after the sidebar and grid padding; the final row is padded with invisible items to preserve column alignment. Topic taps open `ArticlePlaceholderPage`, which displays the selected subject/topic but is not a content-backed article yet. The desktop search filters topic labels. The sort button currently only toggles its icon/state; ordering is not yet changed. Topic lists remain a static map keyed by subject display name; unknown subject keys render no topics.

## Audio And Motif Notes

- Samples are mono 16-bit PCM WAV at 44.1 kHz.
- Note synthesis uses a fundamental plus two quiet harmonics and an amplitude envelope.
- Melody notes begin every 110 ms and last 220 ms, creating overlap.
- `playMelody(..., reverse: true)` reverses note order; it does not reverse the sample waveform.
- Each sound gets a separate one-shot player. Android/iOS use an audio context configured to mix with other audio.
- Configured volumes are currently `1.5`; `audioplayers` generally documents volume as a 0.0-1.0 range, so platform clamping may differ.
- The active subject catalog has twelve named mappings, while `SubjectJingles.all` retains seventeen candidate sequences.

Linux native audio builds may require GStreamer development packages. iOS and macOS builds require macOS and Xcode; Windows builds require a Windows host. Plugin/native changes require a full restart rather than hot reload.

## Adding A Subject

1. Add the `icon_key` to `subject_icons.dart` if it is not already in the bundled map.
2. Add a `SubjectDefinition` to `_HomePageState.subjects` in `home_page.dart`, with a unique stable slug.
3. Add the exact subject name to `SubjectJingles._bySubject` and choose a candidate sequence from `all`.
4. Add the exact subject name and topic labels to `SubMenu.topicsBySubject`.
5. Verify the new index gives the intended home-page column/card treatment.
6. Run `flutter analyze` and the focused tests. The app still renders its local subject list; `SubjectDefinition.fromJson` does not connect it to Supabase.
